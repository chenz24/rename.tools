## 目标与判断边界

让重要正文无需点击即可被抓取，让教程步骤能复现预期结果，完善相关页面之间的链接，并统一网站宣传与实际行为。

目前没有证据表明存在全站禁止 Google 抓取的问题，也没有足够数据认定某个问题就是 Google 表现弱于 Bing 的原因。GSC 已确认三个核心 URL 可抓取、已收录且 canonical 正确；发现的图片 503 已做本地修复，但完整生产爬虫/CPU 日志尚未读取。移动端有单次实验室性能基线，GSC 桌面和移动近 90 天真实用户数据均不足；外链情况尚未评估。

## 已确认的现状

| 项目 | 检查结果 | 处理方向 |
| --- | --- | --- |
| 基础抓取 | robots.txt 允许抓取；抽查主要页面返回 200；不存在的页面返回 404 | 保留并做回归核验 |
| 规范地址与语言 | 抽查页面 canonical、hreflang 正确；HTTP、www 跳转到主域名；无对应翻译的指南跳转英文 | 避免无依据地重构 URL 或语言策略 |
| FAQ 正文 | 首页 5 个答案在初始 HTML 正文和未交互 DOM 中为空；答案存在于结构化数据中 | 服务端输出完整答案，保留折叠交互 |
| 场景内容 | 首页仅渲染当前场景，其他场景正文依赖点击 | 预先输出各场景核心内容 |
| 内容覆盖 | sitemap 有 61 个 URL，指南为 5 个主题的英中版本 | 优先完善现有内容，新增主题由需求证据决定 |
| 内链 | 首页正文只有工具入口和 GitHub 链接；首页、功能页没有直达具体指南的链接 | 在相关内容处增加具体教程链接 |

| 隐私文案 | 线上加载 Google Analytics、Umami、Cloudflare Insights；文案仍声称无追踪、无统计脚本 | 按真实实现更新各语言文案 |
| About | 页面主要是重复介绍与技术栈，缺少维护背景；抽查首页、功能页导航没有 About 入口 | 补充可核实信息及入口 |

## 第一阶段：修复可直接确认的问题

### 1. 让 FAQ 与场景正文无需交互即可获取（P1）

涉及文件：

- `src/app/[locale]/page.tsx`
- `src/components/ui/accordion.tsx`
- `src/components/home/UseCaseDemo.tsx`

实施：

1. FAQ 优先采用服务端输出答案的原生 `details/summary`，或确认能始终挂载正文的现有组件配置。答案保持用户可展开阅读；若使用 `forceMount`，同时正确处理关闭状态的显示和可访问性。
2. 场景模块输出全部场景的标题、说明与必要示例，再用交互控制显示。避免只把文本放在 JS 数据或 JSON-LD 中。
3. 保留现有布局、键盘操作及移动端体验；只向用户和爬虫提供同一份内容。

验收：

- 原始 HTML 的内容节点中包含 5 个 FAQ 答案及全部场景核心说明，排除 script/style 后仍可提取。
- 浏览器完成渲染但未点击时，相关正文已在 DOM 中；各折叠项和场景切换仍正常。
- FAQ 可见答案与对应 JSON-LD 内容一致。
- 七种语言均不出现翻译缺失、重复正文或布局明显异常。

### 2. 校正隐私与统计描述（P1）

涉及文件：`messages/*.json`、`src/components/GoogleAnalytics.tsx`、`src/components/UmamiAnalytics.tsx`、相关隐私/功能页面。

实施：

1. 核对生产环境实际启用的统计工具、配置及事件，区分已观察到的脚本加载与尚未确认的数据采集细节。
2. 将“文件本地处理、无需上传”与“网站访问统计”分别说明，删除不准确的“完全无追踪”“没有统计脚本”等绝对表述。
3. 同步修正首页摘要、功能页、FAQ、隐私页的七种语言文案。
4. 核对隐私页中仍写 Vercel 的托管说明，与实际部署情况保持一致；说明可选 TMDb 功能的第三方请求。
5. 本阶段保留现有统计配置；不因文案修复直接停用或新增统计服务。

验收：

- 所有语言的隐私承诺与已核实实现一致，不把文件处理和访问统计混为一谈。
- 对尚未核实的数据字段不作承诺；不把此次文案修正描述成已证实的排名恢复措施。
- 不输出环境密钥，不改动文件处理和重命名行为。

### 3. 跑通现有五篇教程（P1）

涉及文件：`src/lib/guides/content.ts`、`public/guides/screenshots/`；必要时补充针对示例的规则验证。

实施：

1. 对入门、照片日期、正则、序号、音乐/视频五个主题逐一建立输入文件名、完整规则配置、预期输出的对应关系。
2. 修正入门示例中日期插入、原编号处理、序号位置或替换方式未说明的问题。
3. 为正则示例提供可直接复制的 pattern、replacement、flags，并明确作用范围是否包含扩展名。
4. 明确 `{date}` 与 EXIF 拍摄日期的区别、缺失元数据的处理，以及直接重命名与脚本导出的浏览器限制。
5. 用应用示例模式或临时测试文件验证，确保英中说明与截图一致；只在实质内容改变时更新修改日期。

验收：

- 每个展示的前后结果都能按文中步骤复现。
- 至少覆盖扩展名保留、序号位置、正则捕获组和缺失元数据等相关边界。
- 对易回归的规则示例使用现有测试框架做有意义的验证；不为纯文案改动新增机械测试。
- 若发现规则引擎缺陷，单独记录并限定修复范围，不默默通过改写教程掩盖问题。

## 第二阶段：改善内容连接与可信度

### 4. 增加相关内链（P1）

- 首页场景模块：照片、音乐/视频等内容链接到相应指南。
- 功能页：正则、序号、元数据相关说明链接到对应指南。
- 指南页：保留相关指南与工具入口，链接文字明确说明目标内容。
- 使用实际 `<a href>` 链接；英中指向同语言指南，其他语言明确标注英文指南并直接指向英文规范地址。
- 先完成普通链接；“一键加载示例/规则”作为独立增强项，在现有教程准确后再实施，避免扩大首轮范围。

验收：从首页或功能页相关正文可直达具体指南；链接无 404、无不必要重定向；移动端同样可访问；不存在只有点击 JS 按钮才能发现的目标 URL。

### 5. 补充 About 与维护信息（P2）

- 添加页脚 About 入口。
- 根据已公开且可核实的资料说明维护者、项目目的、开源仓库、问题反馈及更新渠道。
- 指南展示真实作者或维护主体及相关链接；不编造资历、用户量或背书。

验收：用户能找到维护与反馈渠道；事实与公开仓库一致；各语言内容保持一致。

## 第三阶段：用 GSC 决定后续优化

可与前两阶段并行收集数据，不阻塞已确认问题的修复。

### 6. 建立搜索表现基线

收集最近 3 个月的：

- 搜索表现：查询、页面、点击、曝光、CTR、平均排名，按国家及设备拆分，并区分品牌词与非品牌词。
- 页面索引：已收录页面、主要未收录原因、sitemap 读取状态。
- URL 检查：英文首页、工具页、代表性指南的抓取状态、Google 选定 canonical 与渲染结果。
- 如发现访问异常，再核对 Cloudflare 对已验证 Googlebot 的拦截和服务器错误日志。
- 移动端 Core Web Vitals：有真实用户数据则据此判断；无数据时用实验室测试定位，不把单次测试当作真实用户表现。

决策规则：

| 数据表现 | 下一步 |
| --- | --- |
| 重要页面未被发现或抓取 | 优先排查内链、sitemap 及爬虫访问 |
| 已抓取但未收录 | 结合具体页面检查内容价值、重复与 canonical，不能一概归因于内容短 |
| 已收录且排名低 | 对照实际查询深化内容与任务完成能力 |
| 排名尚可但 CTR 低 | 按查询优化标题、摘要及结果展示，并观察变化 |
| 同一查询的首页与工具页反复切换 | 再决定页面定位、标题区分和内容调整；不直接对工具页 noindex |

### 7. 按证据扩展任务型内容（P2）

2026-09-21 决策：现有查询可见部分仅覆盖 24/81 次点击，照片指南虽有 267 次曝光但页面过滤后的查询表无数据。先完善并观察已有页面；候选新页暂缓，不把样本缺口当作零需求或随意据此改标题。

候选主题：移除前缀/括号/空格、按 EXIF 拍摄日期重命名、Windows/Mac 操作、Plex/Jellyfin 剧集及字幕命名。

优先改进已有相关页面，避免创建内容高度相似的页面。新增页必须有独立任务、可复现步骤、真实限制及明确工具入口。发布后再加入正确的 sitemap、canonical、hreflang 与内链。

## 验证与交付顺序

1. 正文渲染修复：检查原始 HTML、未交互 DOM、展开/切换操作及移动端布局。
2. 文案与教程修复：运行可复现示例，核对语言及截图一致性。
3. 内链与 About：检查链接目标及各语言路由。
4. 运行与变更相关的现有测试、类型检查和生产构建；lint 结果区分新增问题与既有问题。
5. 在预览中抽查首页、功能页、工具页、指南及不存在路径；核对状态码、canonical、hreflang、robots 和 sitemap，确保不误加 noindex。
6. 部署后复查生产页面并记录上线日期；通过 GSC 检查重要更新页面。部署属于后续实施阶段，本计划不执行部署。
7. 上线后先确认抓取和索引，再比较更新前后各 28 天的页面/查询表现；按语言、国家、设备解释变化，考虑重抓取延迟、季节性与外部波动，不承诺固定时间内提升排名。

## 本轮不优先做的事

- 堆叠 `meta keywords` 或调整 sitemap `priority/changefreq`：Google 不将前者用于排名，也忽略后两项。
- 把 FAQ/HowTo 结构化数据当作排名增长主方案；正文可用性优先。
- 无数据依据地合并首页与工具页、修改 canonical、给工具页加 noindex、删除翻译或法律页面。
- 为制造新鲜度批量刷新日期，或批量生成缺乏独立价值的关键词页。
